Brain layer (src/sim/brain.js, scripts/relay.mjs, src/data/prompts.js), built for issue #40, Mind log added in #61.

- Decision points: townPlan (zone for next trip + crypt call yes/no; hook = `townZone(a)` at town step 2 in heroes.js, `brainOk(a,'crypt')` in dungeon.js pool filter), fightOrFlee (`brainFight(a,m,mh)` in the heroes.js fight case, asks once when HP<50% vs mob 1+ levels above), say (`brainLine(a,trigger,ctx,tableText)` in chat.js; since #71 no cache: answer parked in module `ready` map, spoken by `sayTick` (every brainTick) via chat.js `speak()` if `clk-askedAt<=CFG.sayFresh` (4 sim s), hero can speak, and for spot/flee/duel the same state family + same living target (flee uses `a.spotTgt`); else settled `late`. `CFG.aiQuietTable` (default true) holds the table line in `held` for the window; released on expiry or when the request fails. With quiet on, a dead-relay brain run differs from plain only in chat buffer lengths; braincheck fp 'loud' (quiet off) must be fully identical).
- Parties (PR #74): heroes.js gate calls `partyZone(a)` for party members (townZone for solo). First call per trip (p.set, only when leader has a brain) lets the leader's fresh plan set p.zone if in `partyLegal(p)` (around(zoneFor(weakest lvl, leader home))), else overruled. Leader in a party is offered partyLegal + snapshot.leadParty. `zoneQ(a)`: only solo heroes or a leader before p.set get the zone question; followers get cryptCall (lvl>=7) or nothing. Hooked at departure, not seekParty, because the leader's plan is often still in flight when the party forms. Gate order since merging #73: `if(dmDepart(a,c)){brainJob(a);break}` then partyZone/townZone - a DM job outranks zone plans; brainJob settles the solo/leader plan 'overruled' ('the party took a job: <title>') and closes p.set; followers log 'follows the party on <title>'. braincheck sets setDmPolicy({pickHook:()=>null}) so test heroes never take jobs (was 1-in-3 flaky).
- Pattern: fire-and-forget fetch, answer validated against options the sim sent, parked in `a.brainPlan.{town,fight}` (with `mid` = Mind entry id) applied at the NEXT decision point (say lines: in the moment or dropped, see above). Since #61 a townPlan answer that arrives after the hero left town is recorded as `late` and NOT parked. No RNG, no awaiting.
- Saved plain data: `a.brain`, `a.brainPlan`, `a.mind` (cap 30, newest first), `a.mindSeq`, `S.brainHeroes`. Transient (module-level): busy, offline, line cache, inflight, clock. Brain clock restarts at load, so plans stamped in the future are ignored; pending Mind entries orphaned by a reload are swept to `superseded`.
- Mind entry: {id,t:'D3 07:12',gameMin,kind,options,snapshot(exact object sent),choice,line,reason,ms,outcome,error?,scripted?,crypt?,trigger?,usage?,sent?:{id,system,user|userSame}}. Outcomes: pending -> applied | rejected | late | offline (unreachable, timeout, or relay {error}) | superseded | overruled (legal answer the party would not follow; amber in Mind tab). Kind 'follow' = token-free note (snapshot null, ms null, leader name) logged by an AI follower at the gate. First final outcome wins (`settle`).
- Relay protocol: POST /decide {kind, snapshot} -> {choice, crypt?, line?, reason?, sent:{id:'townPlan@2', system, user}, usage:{in,out,cost}} | {error, sent?}; GET /health. 127.0.0.1:8787; CORS only http://localhost:5173; 2.5 s abort; model `claude-haiku-5-5` via @anthropic-ai/sdk, `thinking:{type:'disabled'}`, `output_config:{effort:'low', format:{type:'json_schema'}}`. User content = JSON.stringify(snapshot). `--verbose` / RELAY_VERBOSE=1 appends {ts,kind,hero,system,user,response,usage,ms,error?} lines to logs/relay.jsonl (gitignored).
- Schema: townPlan {choice enum, crypt bool, reason string}; fightOrFlee {choice enum, line, reason}; say {line}; cryptCall {crypt bool, reason} (party followers only, no options; OPTION_KINDS in prompts.js lists kinds that need options). Structured outputs do not support maxLength, so the length is in the description/prompt and `cleanReason` (prompts.js, shared by relay and sim) truncates to 120. PROMPT_VERSION=3 (bump on any prompt/schema change). max_tokens townPlan 110, cryptCall 90, fightOrFlee 130, say 60.
- Measured live (user's relay, 2026-11-01): townPlan and say succeed on claude-haiku-5-5 at ~$0.00008 per call (~800 in / ~30 out tokens); one townPlan round trip through the sim ask path took 1285 ms. Mock: ~600 ms in the smoke run is the mock delay, not real. Reason field adds ~25 output tokens (~$0.0000125) per call - not yet measured live.
- Test approach: scripts/braincheck.mjs (mock relay + fake model client + seeded child processes proving a dead relay leaves the sim state identical, plus Mind outcome cases and the verbose log). Math.random must be patched before importing the sim. Several pre-existing checks are timing-sensitive; wait on the Mind entries themselves, not on global stats (detached entries from earlier phases inflate stats.rejected / timeouts).
- Stubbed-DOM smoke of src/main.js: needs ResizeObserver, requestAnimationFrame, a canvas getContext proxy and Element.closest/matches for '[data-x]' and '.cls[data-x]'; drive frames by hand.
- Sandbox note: Bash tool refuses heredoc-heavy or variable-in-option commands in worktrees; write scripts with the Write tool and run them plainly. Python on Windows writes CRLF; strip with sed after patching.
